## The story judges should remember

**ECHKILI Evidence Lab — Proof before Diagnosis**

Incomplete technical observations can produce plausible but unsupported answers. ECHKILI Evidence Lab shows a different interaction: every tentative hypothesis cites its inputs, contradictory records trigger explicit caution, and a new observation visibly changes the reasoning trail. Qualified people stay in charge.

This is a **new, self-contained 2026 hackathon prototype**. Fictional solar irrigation pump reports are used for demonstration. No private ECHKILI commercial implementation, user records, inventions, or protected assets are published here.

## One winning demo flow

1. Open a synthetic equipment case with provenance-labelled observations.
2. Select two compatible observations: see preliminary, evidence-linked reasoning.
3. Request **Meta Muse Spark 1.3 Standard** annotations (actual Model API call only after approved account and credit checks); each model-supported claim must pass a source-ID validator.
4. Add an observation that conflicts with another: visualize the contradiction, higher uncertainty, and a human-verification handoff.
5. Show a **before / after evidence delta**: which hypotheses changed, which evidence caused the change, and what the model could not establish.
6. Show the evaluation dashboard: false source-ID references rejected, missing-evidence abstention, contradiction detection, and controlled inference expenditure.

### Why this is more than a chatbot

- Deterministic evidence and safety layer wraps around the model.
- Inputs and outputs use stable IDs and machine-checkable structure.
- Contradictions are explicit objects, not hidden in natural-language prose.
- The history makes changed conclusions auditable.
- Synthetic test cases allow reproducible measurement.
